# magari.cc 設計メモ

間借り・日替わり店長・レンタル○○・ライブ・自助会・オフ会・オルタナティブスペースのための
イベント元締めサイト。Google カレンダー / Google フォーム / X の告知に散らばっている
「いつ・どこで・誰が」を一箇所に集め、フォローと通知で Google カレンダーの役割を置き換える。

## コンセプト

**今日もどこかで誰かが開けている。行ってもいいし、自分が開けてもいい。**

空気は「しょぼい起業」や pha の側に置く。頑張らなくていい、計画しなくていい、とりあえず開けておけば誰か来る。

- **「主催者になろう」と呼びかけない。** 画面の言葉は「開ける」「いる」「店番する」の温度にする。「主催」は共同主催の管理など、役割を指す所にだけ使う。
- **告知する催しでなくていい。** 「18時から店にいます」「公園でなんもしない」が一言で置ける。要るのは「ひとこと・日時・場所」だけで、残り（住所・説明・料金・公開範囲）は会のフォームで畳んである。
- **主語は人。** 一覧の行は「誰が」（顔と名前）を先に、ひとことと場所をその下に出す。顔は先頭の主催のアイコン、無ければその会のハコのアイコン、それも無ければ種別の印（人・ハコ・団体）を handle から決まる貼り紙の色で出す（`ActorFace.svelte`）。主催のいない会（取り込み）はハコを見出しにする。
- **間借りは声をかけて決まる。** ハコのページは料金表より先に「誰に声をかければいいか」（X、`/new?space=handle`）を出す。
- **数を誇らない。** トップに件数の統計は置かない。

UI/UX の型は「意識が低すぎる、しょぼい Luma」。Luma から借りるのは構造だけ（1 枚のページを 30 秒で作って貼れば告知が終わる）。参加登録・承認制・チケット・定員管理・ゲスト一覧・リマインドは借りない。

- **作成画面は会のページと同じ 2 列**（`EventForm` に `flyerId` を渡したとき）。左の自動のビラは打つそばから刷り上がる。ビラの下に型の見本 4 枚（今の内容で刷ったもの）と差し色 5 つが並び、選んだ組で保存する（`FlyerPicker`）。最初に選んである組とビラの傾きは会の ID から決まるので、`/new` の load が先に ID を決めて hidden で送り、保存後も画面で見たビラのままにする（`isShortId` で形を確かめ、もう使われていたら保存しない）。スマホでは大きいビラを出さず型の見本だけにして、打つ欄を最初の画面に入れる。
- **トップ（`/`）は紹介のランディング、`/home` が一覧。** `/` は上に「こんな間」の流れる帯（間借り店舗、日替わり店長、ライブ、自助会、オフ会…）、その下の左に一文とボタン（「とりあえず開ける」と「開いている所を見る」= `/home`）、右にビラ 3 枚を重ねて貼る。最初の画面はそれだけにして、その下に「これから開く間」（近い順に 5 つ、実物を先に見せる）と「なにがうれしい」（行く人・開ける人・ハコを貸す人の 3 列）、「しないこと」（お金をとらない・預からない・取り持たない・隠さない）を置く。カードにせず 1px の線で区切り、件数は出さない。ビラは近い順の実際の会で、まだ誰も開けていなければ見本。ログインしていても `/` は同じランディングを出す（`/home` へは送らない）。ヘッダーの図像はいつも `/` へ飛ぶ。PWA の起動先（`start_url`）は `/home`。`/home` はこれから 7 日の一覧（エリアの絞り込み）で、ログインしていなくても見られる。月のグリッドは `/calendar` にだけ置く。2 つを URL で分けるのは、同じ URL の HTML をログイン状態で変えないため（公開ページを CDN に載せるときに効く）。
- **ナビは図像と字だけで、画面の幅いっぱい。** 中身の幅には揃えず、左端にロゴの図像（ログイン中は `/home` へ）、右端に「まがり」（`/new`）（ログイン後はその右に顔）。「まがり」はこのサイトの主な動作なので、ナビの中でここだけ小さなテープ（primary ボタン）にする（`/new` にいる間は字に戻す）。ログイン前に「ログイン」のボタンは並べない（「まがり」を押せばログインを挟んで `/new` に着くので、入口が 2 つになる。戻ってきた人のためのログインはフッターに小さく置く）。タブは実体の「イベント」（`/home`）と「ハコ」だけで、それぞれ字の左に小さな線画のアイコン（切符、店先）を付け、中身の幅に揃えた位置に置く。一覧（`/home`）・フライヤー（`/wall`）・カレンダー（`/calendar`）は同じイベントの見せ方なので、ナビには並べず、3 ページの上に同じ切り替え（`EventViews.svelte`。状態ではなくリンク）を置く。どれにいてもナビは「イベント」が点く。エリアの絞り込み（`AreaFilter.svelte`）も 3 つの見せ方すべてに置き、選んだエリアは localStorage で引き継ぐ。区切り線・下線のテープ・GitHub のアイコンは置かない。フッターは奥付で、ナビと同じものは繰り返さない。左に「個人が無償で動かしている・広告なし・ソース公開」の 2 行とソース／不具合・要望／MIT License へのリンク、右に規約類と掲載の取り下げ・連絡、ログイン前はログイン。© は置かない（会社の帯に見えるので）。
- **開けた直後は「貼る」を先頭に出す。** `/new` は `/e/{id}?opened` に飛ばし、会のページが「開けました。あとは貼るだけ。」と X・リンクのコピーを出す。共有する URL には `?opened` を付けない。

## 運営の責任を小さく保つ

数を載せるうえで一番の障害は、運営者（個人）に責任が集まること。機能を足すときは、次の 4 つを崩さない。

- **運営は発信しない。** 運営が自分で載せた情報は運営の発信になる。例外は外部カレンダーの取り込みで、本番でも動かしている（合意の取り付けはこれから。写す範囲は下の「外部カレンダーの取り込み」）。それ以外で数を載せる手段は、ハコの管理者が自分のカレンダーをつなぐこと（本人の操作）と、利用者による掲載にする。第三者による掲載は、題・日時・場所・元の告知へのリンクだけ。主催者本人でない人が、個人を主催として載せるのは禁じる（当事者会では、病気や障害を他人が明かすことになる）。
- **預からない。** メールアドレス、問い合わせ、参加表明（誰がどの会に行くか）は持たない。運営への連絡の返信先も X / Misskey の ID でよい。
- **仲介しない。** 決済、予約の成立、利用者どうしのメッセージ、貸し借りの取り持ち（空き枠への応募と承認など）は作らない。ハコ自身の窓口へのリンクに留める。
- **言われたらすぐ消せる。** 申し出の窓口（`/contact`）は無くさない。届いたら運営に通知し、まず非表示にしてから判断し、いつ何をしたかを残す。
- **約束しない。** 利用規約（`/terms`）、プライバシーポリシー（`/privacy`）、掲載と削除の方針（`/policy`）を置く。会のページには「載せた人が書いた内容。行く前に主催の告知で確かめる」と、運営への連絡の入口を出す。

法的な位置づけは、利用者が載せた情報について場の提供者として責任が限定される、という一般的な理解に基づく。専門家の確認は済んでいない。

## 原則

- **場所を持たない人と、場所を貸す人をつなぐ。** 既存のイベントサービスにない「枠を借りてその日だけ店をやる」を一級市民にする。
- **閲覧はログイン不要。** ログインするのは主催者・場の運営者・フォローしたい人だけ。
- **脱 Google、脱メール。** ログインは X と Misskey（MiAuth、任意のサーバー）だけ。メールは確認メールの配送が要るので使わない。パスキーは初回ログイン後に作れる。カレンダーは iCal で出す側に回る。地図と口コミは Google マップへのリンク（API は使わない）、計測は Cloudflare Web Analytics、フォントはシステムフォント。
- **参加者のプライバシーが既定。** 自助会・オフ会の参加記録は公開プロフィールに残さない。参加表明は非公開・匿名可が既定。
- **出口を持つ。** 全データは iCal / JSON で出せる。将来 ActivityPub で配信する。
- **無料枠で永続運用。** Workers Free の 10ms CPU / 100k req/day の中で動かす。

## 概念モデル

| 概念 | 説明 | ActivityPub 対応 |
|---|---|---|
| **Actor（人・場・団体）** | 会を主催する主体。`kind` で `person` / `space` / `group` を区別。全員が同じ `handle` 名前空間を共有し `/@handle` で表示される | Person / Organization / Group |
| **Event（会）** | 主催 Actor × 日時 × 場所。場（space）は任意。場なし（公園・オンライン・相手の指定場所）やオフ会もここ | Event |
| **Series（定期開催）** | 自助会向け。RRULE で Event を先々まで展開する | — |
| **Slot（枠）** 段階2 | 場が公開する空き枠。応募 → 承認で Event に昇格 | — |
| **Follow** | ユーザーが Actor をフォローし、マイ予定に集める | Follow |
| **Attendance** 段階3 | 参加表明。既定で非公開、匿名可 | Join / Accept |

### オフ会を自然に扱うための決め事

- **ユーザーは登録時に自分の Person Actor を自動で持つ。** 場や団体を作らなくても、誰でも会を立てられる。
- **会は主催 Actor を複数持てる**（`event_hosts`）。共同主催のオフ会のため。
- **住所を載せず「主催に聞いてください」と出せる**（`locationVisibility` = `attendees`）。自助会・オフ会向け。参加者という概念は持たないので、知らせるのは主催自身。
- **会の可視性**は `public` / `unlisted`（URL を知っている人だけ）。自分だけに見せたい間は下書きにする。

## 安全の決め事

- **別のサイトからの書き込みは断る。** GET・HEAD・OPTIONS 以外で `Origin` がこのサイトと違えば 403（`hooks.server.ts`、判定は `src/lib/server/cross-site.ts`）。SvelteKit が自前で見るのはフォームの送信だけなので、JSON や本文の種類が無い要求もここで止める。`Origin` を付けない呼び出し（curl、Cron）は通る。
- **読み込んでよい先は CSP で縛る**（`vite.config.ts` の `csp`）。スクリプトは自サイトのファイルと、SvelteKit が吐くインライン（ハッシュ）だけ。nonce にしないのは、公開ページを CDN に載せても同じ HTML を配れるようにするため。外部のスクリプトや接続先を足すときは、ここを直す。いま許している外部は Cloudflare Web Analytics だけ（Cloudflare がブラウザ向けの HTML にだけ差し込むので、ローカルでは出ない。CSP を変えたら本番をブラウザで開いて確かめる）。`{@html}` とインラインの `<script>` は使わない。
- **どの応答にも付けるヘッダー**は `hooks.server.ts` の `SECURITY_HEADERS`（nosniff、Referrer-Policy、X-Frame-Options、HSTS、Permissions-Policy）。Worker を通らない静的ファイル（`/_app/…`、`static/`）には付かない。
- 利用者が入れたホストへの通信は `remoteJson` を通す（下の「ログイン方法と ID の対応」）。

## 速さの規約

1〜3 は Workers Cache（Worker の手前のキャッシュ。`wrangler.jsonc` の `cache`）で満たす。決め事は `src/lib/server/cache.ts` と `hooks.server.ts`。

1. **公開ページは HTML ごとキャッシュに載せ、書き込みで purge する。** キャッシュにあれば Worker は動かない。
   - **載せるのは「公開」と書いた応答だけ。** Workers Cache は `cache-control` の無い 200 を既定で 2 時間持ち、鍵に Cookie を入れない。だから `hooks.server.ts` が、`public` と書いていない応答すべてに `private, no-store` を付ける（`cacheHeaders`）。
   - 公開の JSON・iCal・sitemap は `CACHE_PUBLIC`（ブラウザには持たせず、キャッシュに 5 分）。公開ページの HTML は、元にした API の応答と同じ `cache-control` を `load` が写す（`cacheLike`）。公開の間は公開、下書きは `private` と、決めるのは API の側だけ。
   - **公開の応答は、だれが見ても同じ中身にする。** HTML にログイン中の人を入れない（ルートに `+layout.server.ts` を置かない）。ヘッダーの顔と「編集」リンクは、ブラウザが表示専用の Cookie（`me`。`src/lib/viewer.ts`。handle・名前・顔・編集できるページ、HttpOnly でない）から読む。サーバーはこの Cookie を信じない（編集できるかはセッションで確かめる）。Cookie は、公開でない応答を返すたびに `hooks.server.ts` が今のログイン状態に合わせる（ログインのあとは必ず `/me` などの公開でないページに着く）。`src/lib/guards.spec.ts` がこの 2 つを見張る。
   - **purge は、ログイン中の人か Cron の、通った書き込み（GET 以外）のたびに、札 `data` の付いた応答をまとめて消す**（`shouldPurge`。`cache.purge`、API トークンは要らない）。ログインしていない人の POST では消さない（回数の上限を使い切られる）。purge が世界中に届くまで 0.3 秒ほどかかるので、0.5 秒待ってから応答を返す（保存のあとの転送先で、直した本人に古いページを見せない）。書き込みの種類ごとに呼び分けない（呼び忘れた所だけ古い中身が残るのを防ぐ）。Cron の取り込みと繰り返しの延長も POST なので消える。purge の回数には上限があり（1 分に 5 回、貯めは 25 回）、届かなかったときに古い中身が残るのは 5 分まで。「いまから先」の一覧が時間で古くなるのも 5 分まで。
   - 落書き（`/api/graffiti`）は purge せず 60 秒で切る（描くたびに purge すると上限に当たる）。描いた本人は 60 秒のあいだ別の URL（`?after=`）で取り直すので、自分の線は消えない。`/i/…` の画像は中身が変わらないので札を付けず、書き込みでは消さない。
   - 鍵には Worker の版が入るので、デプロイのたびに空になる。
   - 確かめ方: 応答の `Cf-Cache-Status`（`HIT` / `MISS` / `BYPASS`）。ローカル（`vite dev`、`wrangler dev`）にはこのキャッシュが無いので、ヘッダーまでしか確かめられない。
   - Workers Cache を有効にすると、静的ファイル（`/_app/…`）への要求も Workers の要求数に数えられる、と Cloudflare の文書にある（静的ファイルの文書とは食い違う）。無料枠（1 日 10 万）に近づいたら、ここを見直す。
2. **クライアント遷移は Worker を通さない。** `+page.ts`（universal load）からキャッシュ済みの JSON エンドポイントを fetch する。`__data.json` 経由にしない。URL に「いま」を入れるときは丸める（`weekAhead`。ミリ秒まで入れると毎回別の URL になり、載らない）。
3. **読み取りで D1 に触るのはキャッシュミス時だけ。** APAC primary でも東京から往復 70ms かかりうる。
4. **日本語 Web フォントを使わない。** システムフォント。
5. **Service Worker は、回線が切れたときに前に見たページを出す**（`src/service-worker/index.ts`、決め事は `src/lib/offline.ts`）。
   - **回線があるあいだは何も変えない。** いつも回線の応答を出し、その写しを取っておくだけ（ネットワーク優先）。前の中身を先に出して裏で取り直す形（SWR）にはしない: 中止や変更を、古い中身より後に見せることになる。速さは手前のキャッシュ（上の 1）で出す。
   - 回線が切れていれば、前に見たページ・JSON を出す。見たことのないページは `static/offline.html`。出ているのが前の中身だと分かるよう、オフラインのあいだは本文の上に一言出す。
   - **取っておくのは、サーバーが「公開」と書いた応答だけ**（`keepable`）。本人だけのページ（`/me`、下書き）は端末に残らない。ログインと運営の口、落書き、画像（大きいのでブラウザ自身のキャッシュに任せる）には手を出さない。
   - 取っておいたものは版をまたいで持ち、300 件を超えたら長く見ていないものから捨てる。名前にハッシュの入ったファイル（`/_app/immutable/…`）だけは、持っていれば回線に出ない。
   - はじめて開いたページは Service Worker が動き出す前に読み込まれているので、ページの側から URL を知らせて取っておく（`+layout.svelte` の `warm`）。回線に出るのはページの HTML の 1 回ぶんだけ。
   - 型は `src/service-worker/tsconfig.json`（Kit 3 の決まりで、ルートの tsconfig からは外す）。`pnpm check` が合わせて見る。確かめるのは `pnpm preview`（`vite dev` では動かない前提で見ない）。
6. **管理画面は SPA 寄り。** Worker は JSON を返すだけにして 10ms に収める。
7. Early Hints / HTTP/3 / Tiered Cache / Brotli を有効化。画像は AVIF + サイズ指定。
8. `data-sveltekit-preload-data` と Speculation Rules で次ページを先読み。

## 段階

1. **元締めカレンダー**: Actor / Event / Series の登録、公開ページ、OGP、X 共有、iCal 配信、フォロー、マイ予定。パスキー + X ログイン。
2. **間借り枠**: Space が Slot を公開 → 応募 → 承認で Event に。
3. **参加と通知**: 参加表明（非公開既定）、定員、キャンセル待ち、PWA + Web Push。
4. **後回し**: レンタル○○への個別依頼、決済、.ics 一回限りインポート、ActivityPub 配信、X 自動投稿。

## X 連携

- ログイン: better-auth の `twitter` プロバイダ（OAuth 2.0 + PKCE）。
- 共有: intent URL + OGP 画像。API 不要。共有文は「題 / 日時 / 📍ハコ（無ければ場所の名前かオンライン）」の 3 行（`src/lib/share.ts`）。リンクカードの説明も日時とハコから始める。
- 自動投稿: 段階4。X API Free 枠の投稿上限を確認してから。

## UI 言語

参照元は 2 つ。配置と部品の文法は liblib.page（`liberated-library` リポジトリ）、質感と空気はイベントバーの公式サイトによくある作り。

- **テープの使いどころ**: ガムテープ（アクセントの茶の塗り）は「題・押すもの・いま選んでいるもの」にだけ使う（見出しの 1 語、セクション題の下線、primary ボタン、ナビの「まがり」、選んだ絞り込み、今日の日付）。タグや予定の 1 件ずつには貼らない。画面の中でテープが目立つのは数か所まで。
- **面**: 黒いアスファルト。地はほぼ黒で、折れ目の光と砂粒は弱く残す。画像ではなく SVG の `feTurbulence` を 2 層（細かい粒子 + 大きなムラ）重ねて CSS だけで作る。
- **色**: アクセントは「黒いアスファルトに貼ったガムテープ」の茶 1 系統（`accent` #c4874a / `accent-2` のグラデーション、`accent-ink` 文字、`accent-soft` 16% 背景、`accent-border` 50% 枠）。primary ボタンはテープに黒マジックの字（濃い文字色）。
- **文字**: 見出し・会の名前・人の名前・日付の数字は明朝、UI と本文はゴシック。小さなラベルは太字で字間 0.12em。Web フォントは使わない。
- **ヘッダー**: 高さ 64px、帯は見せない（一番上では地の色を敷かず、アスファルトの上に字が直接載る）。スクロールして本文が下を通る間だけ地の色を敷き（スクロールし始めの 120px で少しずつ濃くする。`--nav-tint`。濃さはナビの高さの中で上から下へ薄くなる: 上端 96%、字のある中ほど 84%、下端で 0）、明るいビラや看板が通ってもナビの字が読めるようにする。上に固定し、下を流れる本文は下端へ向けて消えるぼかし（`.site-header::before`）で溶かすので、字が重ならず帯にも見えない。ロゴは図像だけ、文字だけの小さなナビ。現在地は字の色を濃くするだけ（ほかは muted）。
- **セクション題**: 明朝 + 6px のグラデーション下線（`.section-title`）。日付の区切りは両脇に罫線（`.day-rule`、「―― 題 ――」）。
- **一覧**: カードではなく上下 1px の罫線リスト（`.rule-list`）。`[時刻 tabular][顔][小さく muted の名前 @handle / 明朝のひとこと / muted の場所]`。目立たせるのは会の名前で、誰の会かは上に小さく添える。hover は `accent-soft` の背景だけ。日付の区切りの破線は 2px で薄く。
- **会の詳細**: 定義表（`.defs`）は面で塗らず、一覧と同じ 1px の線で区切る。左に小さなラベル、右に値。
- **カレンダー**: 予定は塗りの札にせず字だけ（hover で `accent-soft`）。まとめ（同じ主催の多い日）だけテープ色の字。
- **パネル**: ぼかしを使わない、線 1 本の平らな面。
- **ボタン**: primary は 200% 幅のグラデーションが hover で流れる + 赤い影。secondary は枠線 1px のピル。影や浮き上がりは他では使わない。
- **装飾**: ヒーローはキーワード 1 語だけをガムテープに載せる。記号は `›` と `·` のみ。
- **段ボール**: ハコ（箱）のページの上部カードは段ボールの看板（`.cardboard`）。クラフト紙の地、繊維のざらつき、中芯の波が透ける縦の帯、湿気で濃い縁を CSS と SVG フィルタで作り、上辺をガムテープでアスファルトに貼る。中の色トークン（text / muted / line / accent-ink など）はこのクラスの中だけ焦げ茶に差し替える。
- 部品は `src/routes/layout.css` の `@layer components` に置き、トークンは `@theme` にだけ書く。

## 外部カレンダーの取り込み

各団体は今まで通り Google カレンダーで運用し、まがりが公開 iCal を定期的に読んで鏡写しにする。Google の API や認証は使わない（iCal は標準形式なので、別のカレンダーに移っても同じ経路で読める）。

- **写すのは題・日時・場所・元へのリンクと、説明文の頭 120 字だけ**（`normalize.ts` の `excerpt`）。全文は元の告知で読んでもらう。説明文に告知ページが無い会は、取り込み元の公式ページ（`sources.ts` の `url`）を告知のリンクにする。会のページには「予定表から写した情報で、本人が載せたものではない」と出す。
- **店の写真**: 取り込み元の公式ページにある店の写真（`sources.ts` の `photo`）は、本番でも R2 に写して、ハコの一覧とページに出す。
- **開発環境の見本**: `IMPORT_SAMPLES=1` の環境だけ、見本として紹介文も写し（`sources.ts` の `summary`）、見た目の確認用にそのまま出す（`nameOnlyIfUnmanaged` の `showSamples`。API の `/api/spaces` と `/api/actors/{handle}` が渡す）。取り込みの有無（`IMPORT_ENABLED`）とは別の旗なので、本番で取り込みを有効にしても紹介文は写さず、出さない。X のアイコン（`sources.ts` の `icon`。R2 へ写す）は本番でも写して出す。
- **合意の前は検索に載せない。** 写した会（`events.source` あり）と、管理者のいないハコ・団体のページ（`/@handle` と `/@handle/past`）は `noindex`。店の名前で検索した人に、公式より先にまがりを見せない。引き取られたページは載る。
- **店あての説明は `/owners`。** 何を写しているか、店は何もしなくてよいこと、取り下げ方、引き取り方を 1 枚に。非公式のページと写した会から飛べる。
- **主催あての説明は `/eventers`。** 店の予定表に載った会がなぜ写るのか、何を写すか、直し方、外し方を 1 枚に。写した会から飛べる。
- **主催ごとに断れる（`blocked_titles`）。** 載せないでと言われた主催の名前や会の名前を運営が `/admin/reports` の「写さない主催」に控える。題にその語が入った会は取り込みで飛ばし（`titleBlocked`。全角半角・大文字小文字・空白は区別しない）、前に写した先の会も「元から消えた会」と同じく消える。主催の名前は題にしか無いので、照らすのは題だけ。
- **本人が載せた会と写した会が重なったら、運営が写したほうを非表示にする。** 自動では畳まない（だれでも即公開で会を作れるので、同じ店・同じ日の会を作るだけで人の会を隠せてしまう）。非表示は再取り込みでも戻らない（upsert は `hidden_at` に触れない）。
- **引き取りは店の X でログインするだけ（`/claim/{handle}`）。** `sources.ts` に控えた店の X の ID（`claimX`）と、ログイン中の人がつないでいる X のいまの ID が同じなら、その場で管理者（owner）にする。ID は引き取りのたびに X へ問い合わせる（better-auth の `accountInfo`）。`user.xUsername` は本人が書き換えられるので使わない。ページの X の欄（`actors.xHandle`）も自己申告なので使わない。控えの無いページと、店の X を使えない人は、今までどおり運営への連絡から。
- **取り込んだ会は、まがりの中で広げない。** 編集はできない（元のカレンダーが正）。この先、会への反応（参加表明など）や ActivityPub の配送を足すときも、取り込んだ会（`events.source` あり）は対象にしない。
- **取り込みはオプトイン。** `IMPORT_ENABLED=1` の環境でだけ `POST /api/admin/import` と `scheduled` が動く（無ければ 404 / 何もしない）。開発は `.dev.vars`、本番は `wrangler.jsonc` の vars に置き、本番は Cron（`triggers.crons`）で毎時走る。掲載の合意はまだ取れていないので、申し出があればすぐ外す（掲載拒否リスト）。止めるときは vars の `IMPORT_ENABLED` を消す（Cron は繰り返しの間にも使うので残す）。
- 取り込み元は `src/lib/server/import/sources.ts`。1 取り込み元 = 1 Actor（場または団体）+ 複数カレンダー。
- パーサは `ics.ts`（終日 / UTC / TZID=Asia/Tokyo、折り返し、エスケープ、RRULE、EXDATE、RECURRENCE-ID）。繰り返しの展開は `rrule`（JST の壁時計を UTC に見立てて展開し、最後に戻す）。
- `normalize.ts`: 終日予定の題に「13-17」「17:30~」「11-16時」と時刻を書くカレンダーがあるので、それを読んで時刻付きにする。説明文が `<a href>` だけのカレンダーは、そこから告知ページを取り出す。
- `run.ts`: 今日の 1 日前から 120 日先までを対象に、ID を「取り込み元 + UID + 回」のハッシュで固定して upsert し、元から消えた会は消す。D1 の bind 変数上限（100）のため 1 行ずつの文を batch で送る。
- 起動: 手動の `POST /api/admin/import`（`IMPORT_TOKEN`）。本番は Cron（`worker.ts` の `scheduled`、毎時 15 分）。
  - adapter-cloudflare は wrangler 設定の `main` の場所を毎回消して生成物を書くので、adapter には `wrangler.adapter.jsonc` を渡し、`wrangler.jsonc` の `main` は手書きの `worker.ts` にする。`worker.ts` は生成物の `fetch` をそのまま出し、`scheduled` で自分の `/api/admin/import` を叩く。
  - adapter は `pnpm dev` の bindings もこの設定から読む。`wrangler.adapter.jsonc` には D1・R2 が無いので、`platformProxy.configPath` で `wrangler.jsonc` を読ませる。
- 取り込んだ会は `events.source` / `source_uid` を持つ。取り込み方法（Google カレンダーなど）は画面に出さない。
- 取り込み元のハコは、名前・公式へのリンク・X の handle と、`sources.ts` の `area`（`actors.region`）、店の写真、X のアイコン、それに `IMPORT_SAMPLES=1` の環境では見本用の紹介文を持つ。掲載拒否リスト（`blocked_handles`）にある handle の取り込み元は飛ばす。引き取られて管理者のいるページは取り込みで書き換えず、会だけを写す。
- ハコのページは、人のプロフィールと同じく名前の左に丸いアイコンを出し、上部のバナーは出さない。アイコンは `avatar_url`、無ければ `header_key` の写真の中央を丸く切り抜く。人と団体のページは今までどおり写真を上部のバナーにする。
- フリカレ（freecalend.com）は iCal を出さないので `freecalend.ts` で読む。公開ページの JS が叩く `POST /open/data` を同じ形で呼ぶ。
  - 本文の `keys` は `{"data":[[キー, 版, 版, [["ok-{mem}-all-r-cald",true]], []], …]}` を 2 重に URL エンコードしたもの。キーは月 `cald-{mem}-{y}-{m}` と日 `cald-{mem}-{y}-{m}-{d}`。版に古い値を送ると、中身のある日だけ `set` で返る。
  - 1 日 1 枠で題しかないので、JST の終日予定に見立てて返し、題の時刻（「16-21時」など）は iCal の取り込み元と同じく `parseEdenTitle` で読む。空・「休み」・「仮予約」は会にしない。
  - 非公開の内部 API なので、形が変わったら取り込みは 0 件か例外になる。取り込み結果の `fetched` を見て気づけるようにしておく。
- 題に時刻が無い 1 日の会は、店の営業時間（`sources.ts` の `storeHours`。公式の店舗ページから写した）に置く。題に「昼」があれば昼の営業時間（`dayHours`）に置き、昼の営業時間が分からない店の昼の会は終日のまま。複数日にまたがる会も終日のまま。題の頭の「昼14-18時」のような時刻は `parseEdenTitle` が読む。

## 大量フィードの見せ方

同じ主催者の会が 1 日に多数ある（まとめサイトの取り込みなど）ときは、一覧では 1 行（`GroupRow`、4 件以上）、カレンダーのセルでは 1 チップ（3 件以上）に畳む（`collapseByActor`）。全件はその主催者のページで見る。特定の団体をハードコードしない。

## 主催者側の動線（段階1の後半）

公開ポリシーは **A: 誰でも即公開**。登録すれば即一覧に載り、荒らしは事後に消す。承認制は必要になってから。

| `/i/{key}` | R2（MEDIA）の画像。キーは乱数なので immutable でキャッシュ |
| `/contact` | 運営への連絡（掲載の取り下げ、ページの引き取り、その他）。ログイン不要、ハニーポット付き。返信先は X / Misskey の ID でよい（メールは求めない）。`reports` に入り、`REPORT_WEBHOOK_URL` があれば運営に知らせる（送るのは種別と対象だけ） |
| `/admin/reports` | 運営者（`ADMIN_HANDLE` の本人）だけ。連絡の受信箱（対応済みにしてメモを残す）、非表示（まず隠す・戻す）、掲載拒否リスト。ほかの人には 404 |
| `/terms` `/privacy` `/policy` | 利用規約、プライバシーポリシー、掲載と削除の方針。フッターと、はじめての登録・会の作成画面から行ける |

ログイン方法と ID の対応（`src/lib/server/miauth.ts`）:

- 1 人のユーザーに、X と Misskey のアカウントをいくつでもつなげる。どれで入っても同じ ID。つなぐのは `/me`（ログイン中に MiAuth を始めると、新しいユーザーを作らず今のユーザーにつながる）。
- Misskey のアカウントは `username@host` で持つ（username は変えられない）。Misskey のトークンは使わないので保存しない。
- つないでいないアカウントで入ると新しいユーザーになり `/welcome` に出る。そこで始めずに入り直してつなげば、空のユーザー（ページも会も無い）に付いていたアカウントは、X でも Misskey でも今のユーザーへ寄せ、空のユーザーは消す（`src/lib/server/link-empty-user.ts`）。中身のあるユーザーどうしはまとめない（運営に連絡）。
- ログイン方法が 1 つも残っていないユーザー（`0013` で Misskey の行を消された人）は、同じ Misskey アカウントで入れば元のユーザーに戻る。本人が外した Misskey アカウントでは入れない。
- 飛ばす前にサーバーが Misskey（とその派生）か `/api/meta` で確かめる。 Misskey のサーバーへの通信は `remoteJson`（`src/lib/server/remote-fetch.ts`）を通す。相手は利用者が入れたホストなので、リダイレクトを追わず、5 秒で切り、本文は 1MB までしか読まない。

- 掲載拒否リスト（`blocked_handles`）にある handle は、人・ハコ・団体のどれとしても作れない。取り下げの依頼を受けたら、まず非表示にし、確かめてからページを消して handle をここに入れる。
- 運営による非表示（`events.hidden_at` / `actors.hidden_at`）: 消さずに隠す。会を隠すと一覧・カレンダー・会のページ（公開）から外れ、主催にだけ「運営が非表示にしています」と見える。ページ（人・ハコ・団体）を隠すと、そのページが 404 になり、ハコ一覧から外れ、そこで開かれる会と、その人・団体が主催の会も出なくなる（`notHidden`）。本人の編集画面にはその旨を出す。対象は `/admin/reports` で「@ID か会の URL」で指定する（`parseModerationTarget`）。
- ログインが要るページ（`/new`、`/spaces/new`）に未ログインで来たら、`?next=` に元の場所を載せて `/login` へ送り、ログインと初回登録（`/welcome`）のあとにそこへ戻す。戻り先はサイト内のパスだけ通す（`src/lib/next.ts`）。
- 中止した間は、編集して保存しても中止のまま（`statusAfterEdit`）。公開に戻すのは「中止を取り消す」だけ。中止は会のページの題と og:title の頭に「【中止】」と出す。
- 作成の二度押しは、同じ ID・同じ題・開始・状態なら成功として続きへ送る（`isSameSubmission`）。内容が違えば保存しない。
- アカウントを消すと、本人が作った間と、主催が本人だけの間が消える。ほかに主催のいる間は残り、本人が主催から外れる。
- フォームの検証と JST → UTC 変換は `src/lib/event-form.ts`（純粋関数、テストあり）。終了が開始以前なら翌日扱い（深夜営業）。
- 書き込みは SvelteKit の form action。`hooks.server.ts` が `locals.actor`（本人のアクター）を載せる。
- ヘッダーのログイン状態と「編集」リンクは、表示専用の Cookie からブラウザが出す（上の「速さの規約」1）。サーバーで組んだ HTML はいつもログインしていない形で、開いたあとに顔が出る。
- 会は「ハコ」欄に場の handle を書くと `space_actor_id` に紐づき、その場のページとカレンダーに載る（`resolveSpace`）。
- 手で立てた会のエリア（`events.area`）は保存のたびに決める（`eventArea`）: ハコの都道府県 → 会場の住所 → 会場の名前 → オンラインの URL。エリアが無いと、一覧とカレンダーをエリアで絞ったときに出ない。
- 共同主催と管理者は、いまは足せない。相手の承諾なしで足せると、本人でない人が個人を主催や管理者として載せられる（「運営は発信しない」の禁止に当たる）ので、足す側だけ止めている。承諾の仕組みは、複数人で管理したいハコが出てから作る。既にいる人は外せる。
  - 会の主催（`event_hosts`）: 主催は会のページに並んで出て、全員が編集できる。会の編集画面で外せる。最後の 1 人は外せない。
  - ハコ・団体の管理者（`actor_members`）: 全員が同じ権限（ページの編集）を持つ。ページの編集画面で外せる。最後の 1 人は外せない。
- **繰り返しの間**（`event_series`、`src/lib/server/series.ts`、`src/lib/repeat.ts`）。選べるのは毎週・隔週・毎月 第N曜日（第5は「最終」）で、決まりは iCal の RRULE の形で持つ。
  - 回は 1 つずつ実体の会として作り、`events.series_id` でつなぐ。一覧・カレンダー・iCal・共有は単発の会と同じに動く。作るのは 90 日先までで、その先は毎時の Cron（`POST /api/admin/series`。`IMPORT_TOKEN`、取り込みの有無とは別に走る）が、1 つの繰り返しにつき 1 日 1 度まで足す。
  - **繰り返しの中の回は、日付のほかは同じ内容。** だから先の回は、いちばん先の回を写して作る（雛形を別に持たない。主催・ビラの型と色・フライヤーの画像も写す。中止は写さない）。
  - **この回だけ直すと、繰り返しから外れる**（`series_id` を消して単発の会にする）。上の決まりを保つため。日付を動かせるのもこのときだけ。
  - **「この先の回もまとめて直す」**は、その回から先の回すべてに内容・時刻・長さを写す（`updateFollowing`）。日付は回ごとのまま。中止した回は中止のまま。
  - 中止と削除は回ごと。消した回は作り直さない（`expanded_until` より前は数えない）。**「この回から先を削除する」**で繰り返しを終える（前の回は単発の会として残る）。回が 1 つも残っていない繰り返しは、Cron が片づける。
  - フライヤーの画像は回どうしで R2 の同じキーを指すので、消すときはほかの会が使っていないか確かめる（`flyerInUse`）。
  - 終わりの日は持たない。開けた人がやめるまで続く。
- フォローとマイ予定は保留（表も持っていない。店や人の予定を追うのは、いまは `/@handle/feed.ics` の購読で足りる）。

## 場のページ（saki-stand.com の上位互換）

間借りを受け入れる店（カレー屋など）が、自前のホームページの代わりに `/@handle` を使えるようにする。参照元は saki-stand.com（コミュニティスタンド咲）。店の紹介に要るものを揃え、加えて「その場で開かれる間のカレンダー」が自動で付く。NEWS と料金表は専用の欄を持たず、紹介文に書く。

| saki-stand.com | まがり |
|---|---|
| 店名・キャッチコピー・コンセプト・使い方・利用の流れ | `name` / `catch` / `summary` / `body`（簡易記法、`Blocks`） |
| 設備タグ（Wi-Fi、電源、厨房…） | `facilities` |
| NEWS | 持たない。知らせたいことは紹介文（`body`）に書くか、間として開ける |
| 出店プラン（時間帯別 / 曜日固定 / 貸し切りの料金表） | 専用の欄は持たない。紹介文（`body`）に「## 出店プラン」と見出しを立てて書く |
| ACCESS（住所、駅、営業時間、定休日、運営、地図） | `address` / `access` / `hours` / `closed_days` / `operator`、地図は Google マップの検索リンク |
| 建物写真 | `header_key`（R2、`/i/{key}`）。ハコ一覧のバナー、ページの丸いアイコン（X アイコンが無いとき）、OGP 画像に使う |
| CONTACT（種別付きフォーム） | 持たない。ハコへの連絡は X の DM など、ハコ自身の窓口に任せる（看板の「X で声をかける」） |
| SNS（X、Instagram）、会社概要、関連サイト | `x_handle` / `instagram` / `operator` / `links` |
| オープンイベントなどの催し | 会（Event）。「ハコ」に自分の場を指定して開く |

- 管理者のいないハコ・団体は、名前・エリア・公式へのリンクと、取り込みで写した X のアイコン・店の写真だけを出す。紹介文は、載せた本人がいないのでサーバーが落とす（`nameOnlyIfUnmanaged`。DB に残っていても出さない）。一覧とページに「非公式」の印を出す。看板から `/contact` へ、ページの引き取りと掲載の取り下げの連絡ができる。
- **ハコへの問い合わせフォームは持たない。** 名前・メールアドレス・電話番号を他人から預かる機能は権利や個人情報の問題に発展しやすく、間借りの相談は X の DM などで足りる。`inquiries` テーブルは `0006_drop_inquiries` で消す。
- 画像は R2 に生のまま置く（変換なし）。JPEG / PNG / WebP、5MB まで。

## フライヤー

会の告知は一枚のフライヤーとして見せる（街のレコード屋やクラブの壁に貼られたチラシの文化）。

- すべての会に自動のビラを描く（`Flyer.svelte`）。題・日時・ハコ／場所・主催だけで描く。自動のビラは「まがりの貼り紙」という 1 つの様式で、アプリと同じ材料（アスファルト・段ボール・ガムテープ・紙）だけで作る。壁には主催が上げたばらばらの画像も並ぶので、自動のビラの側を家の様式に揃えて、壁全体をまがりの壁に見せる。画像生成はせず HTML と CSS で描く（Workers の CPU を使わない）。
  - 型は 4 つ（`FLYER_VARIANTS`）。紙は型ごとに 1 つで、アプリの色から取る。
    - 段ボール `danbo`: 箱を切った札（`.cardboard` と同じ地）にマジックの題。日付はガムテープに書いて端から貼る。箱に刷ってあった天地無用の矢印と折り目が残る。差し色はマジックの下線だけ。
    - ガムテ `gumtape`: アスファルトと同じ黒い紙。題はガムテープに書いて 1 行ずつ貼り（`box-decoration-break: clone`。ちぎった端は `border-image`）、日付は差し色で大きく書く。
    - わら半紙 `gariban`: 一色刷りのおたより。「とき」「ところ」、主催は右下に名前だけ。字も罫も差し色のインク。
    - 貼り紙 `harigami`: 四つ折りの跡がある白い紙。明朝の大きな日付が主役で、曜日は差し色の丸シール。
  - 差し色は 5 つ（`FLYER_COLORS`: 赤・紫・黄緑・ピンク・色なし。ライブハウスの壁やミニコミの刷り色に寄せた、血の赤・謄写版の紫・毒々しい黄緑・ショッキングピンク。保存する鍵は red / blue / green / pink のまま）で、1 枚に 1 色だけ使う。明るい紙にはマジックやインクの濃い色、黒い紙には落書きのチョークと同じ明るい色を当てる。色なしは、段ボールでは白のペンキ、わら半紙では焦げ茶のインク（墨は訃報の黒枠に寄るので置かない）。
  - **型と差し色は開ける人が選べる**（`events.flyer_variant` / `flyer_color`。作成画面と編集画面の `FlyerPicker`）。選んでいない会（取り込んだ会、まとめのビラ）は会の ID のハッシュで決まる（`flyerStyle`）。壁での傾きはいつも ID から決まるので、同じ会はいつも同じ見た目。
  - **題に演出をかけない。** 選んでいない会にはどの題がどの型に当たるか分からず、ふざけた題と切実な題（「死にたいバー」、当事者会の長い名前）が同じ壁に並ぶ。1 字だけ大きくする・色を変える・傾ける・縦に寝かせるは、題の中身を知らずに強調するので使わない。図柄も「題を隠したら感情が読めない」ものだけにする（新しい型は「死にたいバー」を当てて確かめる）。
  - 型を増やすときは、アプリに無い材料を持ち込まない。以前は二色刷りのポスター調と街の紙ものを合わせて 12 型あり、色の組も 9 つあったが、壁もアプリも統一感が無くなったのでやめた。
  - 題は語の途中で折らない。`flyerTitleChunks` が `Intl.Segmenter` で語に分け、助詞・閉じ括弧・1 字の接頭や接尾を隣の語に付けて、切れ目に `<wbr>` を挟む（CSS は `word-break: keep-all`）。`word-break: auto-phrase` は Chromium だけで、英数まじりの題をかえって壊すので使わない。題の大きさは字数でなく見た目の幅で決める（半角は 0.55 字）。
  - 「主催」の字は付けず名前だけ出す。場所と主催が同じ名前なら片方だけ。わら半紙の日付は「11月21日（土）」と日本語で書く。
  - やめたもの: 字を 1 つずつ切り貼りする脅迫状ふうの題、字の横の傍点（どちらも尖りすぎて、合わない会が多い）。放射状の光線に赤い丸の図柄（旗に見える）。特定の団体や思想の記号（拳、星、鎌など）。巨大な頭文字（「死」だけが大きくなる、「18時」が割れる）と同心円（的と催眠の渦）。試作して落とした紙もの: 発車標（人身事故の連想）、黒板と日直（学校の再現を嫌う人がいる）、黒い案内板（斎場）、便箋（遺書）、半券（有料に見える）、レシート（会を商品扱いにする）、吊り紐の札（首吊りの連想）、黒の斜線の網（立入禁止テープ）。
  - 文字の大きさは紙の幅に合わせる（container query の `cqw`）。寸法の基準（`container-type`）は外の箱に置き、余白や配置は中の要素に持たせる（基準の要素自身の `cqw` は外側を基準にしてしまうため）。
- 主催は会の編集画面で好きな画像に差し替えられる（`events.cover_key`、R2 の `flyers/{id}/…`、10MB まで）。縦横比は自由で切り抜かない。差し替えた画像は X で共有したときのカード画像にも入る。「自動のビラに戻す」と会の削除で R2 の画像も消す。取り込んだ会は自動のビラだけ。
- 会のページは 2 列で、左にフライヤー（PC ではスクロールしても左に残る）、右に日時・題・詳細・説明・共有。スマホではフライヤーが先。
- フライヤーの壁（`/wall`、イベントの見せ方の 1 つ。`FlyerWall.svelte`）: これからの間をすべて貼る。上げた画像があればそれを、無ければ自動のビラを貼る。段組みで詰めて貼り、上辺をマスキングテープで留める（`.flyer-pin`）。同じ主催者の多い会は、一覧と同じく 1 日 1 枚のまとめビラに畳む。
- og:image はページの load が返す `ogImage`（パス）を layout が使い、無ければ既定の `og.png`。
- 会の og:image は会ごとのカード画像（1200×630）。左にフライヤー（上げた画像か自動のビラ）を切らずに置き、右に題・日時・場所。X の `summary_large_image` は 1.91:1 に切り抜くので、縦長のフライヤーをそのまま渡さない。
  - `/e/{id}/card`（撮るだけのページ、JS なし）を `/e/{id}/og.png` が Browser Run（`BROWSER.quickAction("screenshot")`）で撮り、R2 の `cards/{id}.png` に置く。最初に取りに来たときに作る。撮るのに 6 秒ほどかかるので、会のページの「X で共有」「リンクをコピー」を押したときに先に取りに行かせる（`warmCard`）。
  - カードに出るものから版を作り（`cardVersion`、`src/lib/card.ts`）、R2 の metadata と og:image の `?v=` に入れる。会を編集すると版が変わり、撮り直す。絵柄を変えたら `DESIGN` を上げる。
  - 無料枠はブラウザ時間が 1 日 10 分、10 秒に 1 回まで。撮れなかった回は上げた画像か `og.png` へ 302 で逃がし、キャッシュさせない。
  - 下書きはカードを作らない。会を削除するとカードも消す。

## ロゴ

サイト名は記号の「◱」（読みは「まがり」）。title・og:site_name・フッター・manifest など名札の位置は「◱」、文中と動詞「まがりする」はひらがなのまま。外の画面に出る名前（MiAuth の appName、パスキーの rpName）と aria-label は、記号だけでは読めないので「まがり」。

ロゴは ◱ を図像化。四角（ハコ）の左下の一角だけを仕切り、そこにガムテープを貼って「人の場所の一角を借りる＝間借り」を表す。アスファルト色のタイル（#151617）にクリーム（#f1efe9）の枠、テープはサイトのアクセントと同じ茶。

- `brand/mark.svg`: タイル付き。favicon、PWA アイコン、OG 画像の元。
- `brand/logo.svg`: タイル無し。ヘッダー用（`src/lib/assets/logo.svg`）。
- 生成物は `static/`（`favicon.svg`、`icon-192.png`、`icon-512.png`、`apple-touch-icon.png`、`og.png`、`manifest.webmanifest`）。PNG は headless Chromium で `brand/*.svg` を描画して作る。
